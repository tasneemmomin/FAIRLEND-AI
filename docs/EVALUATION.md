# LoanLens Empirical Evaluation Protocol
**Rigorous Assessment Framework in the Absence of Static External Datasets**

---

## 1. Prequential (Test-Then-Train) Evaluation for Streaming Models

In standard batch ML, evaluation partitions a fixed dataset into training and test splits. Because LoanLens operates with **zero static datasets**, evaluation follows the **Prequential Protocol** (Dawid, 1984; Gama et al., 2014):

```
For each streaming case t = 1, 2, ..., T:
  1. Input features x_t arrive.
  2. Model predicts probability: p_t = Model_{t-1}.predict_proba_one(x_t)
  3. Officer commits label: y_t ∈ {0, 1}
  4. Record instantaneous prequential loss: L_t = (p_t - y_t)^2
  5. Update model incrementally: Model_t = Model_{t-1}.learn_one(x_t, y_t)
  6. Update ADWIN drift detector with loss L_t
```

### Metrics Tracked:
- **Prequential Accuracy**:
  $$\text{Acc}_t = \frac{1}{t} \sum_{i=1}^t \mathbf{1}(\hat{y}_i = y_i)$$
- **Fading-Factor Prequential Accuracy** ($\alpha = 0.99$):
  $$\text{Acc}_\alpha(t) = \alpha \cdot \text{Acc}_\alpha(t-1) + (1 - \alpha) \cdot \mathbf{1}(\hat{y}_t = y_t)$$

## 2. Calibration & Brier Score Monitoring

A loan recommendation system must provide well-calibrated probabilities rather than overconfident binary predictions.

- **Brier Score (Rolling 50 Cases)**:
  $$\text{BS} = \frac{1}{W} \sum_{i=1}^W (p_i - y_i)^2$$
  A Brier score below $0.25$ indicates superior calibration to random baseline ($0.25$).
- **Promotion Gate**: The online model cannot be promoted from Shadow Mode to Active Recommender unless:
  1. Total labeled decisions $\ge 100$
  2. Balanced class representations: $\ge 20$ approvals and $\ge 20$ rejections
  3. Rolling 50-case officer agreement $\ge 80\%$
  4. Rolling Brier score $\le 0.25$

## 3. Counterfactual Validity, Sparsity & Feasibility Protocol

Counterfactual recourse recommendations must be rigorously verified across four formal dimensions:

| Dimension | Metric / Criterion | Formula / Standard | Target |
|---|---|---|---|
| **Faithfulness (Validity)** | Re-scoring confirmation | $\frac{1}{K} \sum_{k=1}^K \mathbf{1}(f(x_k') = \text{Approved})$ | **100%** |
| **Sparsity** | Number of features altered | $\|x' - x\|_0$ | $\le 2$ features |
| **Actionability** | Immutable attribute violations | $\sum_{j \in \text{Immutable}} |x_j' - x_j|$ | **0 violations** |
| **Monotonicity** | Directional feasibility | Proposed changes align with economic plausibility (e.g. loan decrease $\ge 0$) | **100% compliant** |

## 4. Plain-English Readability & Usability Protocol

### 4.1 Automated Readability Scoring
Every explanation generated by the Plain-English Translator is evaluated using the **Flesch-Kincaid Grade Level formula**:
$$\text{FKGL} = 0.39 \left(\frac{\text{Words}}{\text{Sentences}}\right) + 11.8 \left(\frac{\text{Syllables}}{\text{Words}}\right) - 15.59$$
- **Target**: Grade level between **6.0 and 8.0** (standard conversational English readable by a middle-school graduate).
- **Automated Jargon Check**: A deterministic dictionary audit rejects strings containing blacklisted terms (`SHAP`, `logit`, `coefficient`, `feature`, `vector`, `gradient`).

### 4.2 User Study Protocol (Applicant Usability)
To evaluate borrower comprehension in deployment:
1. **Participant Cohort**: 30 diverse test applicants across educational levels.
2. **Tasks**:
   - Complete intake via voice assistant.
   - Upload salary documentation.
   - Review AI recommendation and counterfactual advice.
3. **Assessment Survey (5-point Likert Scale)**:
   - "I clearly understood why the loan recommendation was made."
   - "The suggested changes were actionable and realistic for my financial situation."
   - "I felt in control of my personal data throughout the process."

---

## 5. Longitudinal Fairness Auditing

On the officer dashboard, group fairness metrics are re-calculated continuously on incoming live streams:
- **Demographic Parity Difference**: $\Delta_{\text{DP}} < 0.10$
- **Disparate Impact Ratio**: $\text{DIR} \ge 0.80$ (compliance with the US EEOC / international 4/5ths rule)
- **Minimum-Sample Flag**: Whenever an audit group has $N < 10$, an alert is displayed preventing premature statistical conclusions.
